# 体检一个已有库（只读）

用户说“检查一下现在的库 / 看看库合不合理 / 评估一下”时用这条流程。目标是给出**能立刻动手的问题清单**，不是夸奖结构，也不是顺手重排目录。

## 步骤

1. **先定位库，不要猜路径。** Obsidian 库的真实路径在 `AppData\Roaming\obsidian\obsidian.json` 的 `vaults[*].path`；`open: true` 那条就是用户正在用的。没有 Obsidian 就按名字特征找（`find ~ -maxdepth 2 -type d -iname '*vault*' -o -iname '*记忆*'`）。
2. **读三层导航再动脚本，顺序固定**：根 `AGENTS.md`（或同等的读取约定）→ 当前状态入口/总索引 → `90-知识库管理/` 里的规则、字段规范、检查清单、待确认事项。读完才知道“什么算合规”，脚本只负责数数。
3. **跑 `scripts/vault_audit.py` 把事实量出来**，不要肉眼数：

   ```bash
   PYTHONIOENCODING=utf-8 python scripts/vault_audit.py "<vault>" [--root-alias <vault文件夹名>] [--skip .obsidian,.trash] > audit.json
   ```

   它只读，输出坏链（按目标聚合、带引用来源）、缺必填字段的页、重名 basename、孤立正式页、滞留收件箱（文件名日期算天数）、`updated` 分布。中文路径要设 `PYTHONIOENCODING=utf-8`，否则 Windows 控制台直接报编码错。
4. **补脚本量不出的四项人工判断**：导航里是否复制了会变化的结论（入口应只导航）；`source_refs` 指向的文件是否真的存在（坏链集中在来源路径 = 结论失去溯源，这是最严重的一类）；恢复说明/维护日志里的“仍缺 N 个”是否还准；`待确认事项` 里 `review_after` 已过期的条目。
5. **报告**：结论先行 → 一行体量（页面数/链接数/坏链数）→ 按影响排序的问题（每条带具体路径和计数）→ 分级处置 → 一个收尾问题。
6. **停在只读。** 评估请求不写库；改动等用户选中某一级再动，并把要改的页面和范围先说出来。

## 判读：哪些算真问题

| 现象 | 为什么是问题 |
|---|---|
| 坏链集中在 `80-原始资料/...` 或 `source_refs` | 引用链断了，页面上的结论变成无来源断言，`confidence` 名不副实 |
| 同一 basename 出现在两个目录 | `[[名字]]` 在 Obsidian 里解析结果不确定，读者/Agent 会随机命中旧副本 |
| 同一目录里两篇 `00-说明`/`00-XX说明` | 重复页，通常是一次迁移或改名没删旧的 |
| 整片目录缺 `domain/kind/confidence/created/source_refs` | 字段规范没落地到那一块，后续检索和验收都失效 |
| 孤立正式页 | 没被任何总览或页面引用，实际等于读不到 |
| 收件箱条目超 30 天 | 半处理状态；若正文早已沉淀进主题页，说明只是忘了归档 |
| `恢复说明` 自称缺失 N 个 | 恢复清单是一次性快照，之后页面被重写或挪位它就过期了 |

## 陷阱

- **恢复/迁移来的库，文件 mtime 全部相同，不能当事实日期用。** 时间和有效性只认 frontmatter 的 `updated`、条目里的观察日，且 `updated` 也不等于事实生效日。
- **“清单说缺” ≠ “真的缺”。** 逐条 `Test-Path` 一遍：路径变了但正文还在的，算现存（挪位/改索引），不算丢失；只有正文确实没有的才进“需重导/永久留空”。把两类混在一起报，用户会以为丢了东西。
- **模板里的 `{{date}}`/`{{title}}` 占位是正常的**，别当成页面缺陷报。
- **不要因为坏链多就断言内容丢了**，也不要顺手“整理目录”——评估阶段重排结构会让用户失去唯一熟悉的地图。
- 体量与历史日志对不上（例如日志自称 100 篇、实际 81 篇）是**重建不全的证据**，如实写成规模差，不要抹平。
- **`pages_missing_fields` 只在库已采用那套字段规范时才算问题。** 新建库按建库参考只用 `title`/`updated` 时，脚本会对每页报缺同样的七项；把口径写进库内维护约定（「本库不采用旧字段规范」），否则每次体检都误报一轮。
- **`wikilinks: 0` 时坏链为 0 是空过。** 导航全用反引号路径的库，脚本根本没检查链接；报告里要么改用 `[[basename]]` 再跑，要么明说「链接未被校验」，不要把它写成「零坏链」。
