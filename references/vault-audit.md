# 体检一个已有库（只读）

用户说“检查一下现在的库 / 看看库合不合理 / 评估一下”时用这条流程。目标是给出**能立刻动手的问题清单**，不是夸奖结构，也不是顺手重排目录。

## 步骤

1. **先定位库，不要猜路径。** 用户已指定目录就直接使用；否则先查已有上下文与约定，再根据环境核实实际库的位置。
2. **先读适用规则**：库入口或 Agent 约定 → 与体检相关的导航、字段规范和维护规则。文件名与层级按实际库确定，不要求所有库都有 `90-知识库管理/`。
3. **运行技能目录下的 `scripts/vault_audit.py`**。先定位已加载技能的实际目录，不假定当前工作目录是技能目录；输出直接留在当前对话，评估只读时不重定向到库内文件：

   ```bash
   PYTHONIOENCODING=utf-8 python <技能目录>/scripts/vault_audit.py "<库目录>" [--root-alias <库文件夹名>] [--req title,updated]
   ```

   它只读，输出疑似坏链、重名短链接、未校验锚点、字段缺失、重名和孤立候选等。`--req` 按本库实际字段规范选择；正式页默认识别顶层目录以 1/2/3 开头、收件箱以 0 开头，实际目录不同需调整 `--formal-prefixes` 和 `--inbox-prefix`。核对 `formal_pages_checked` 是否覆盖本库正式页面；为 0 或范围不足时，不能把孤立页为 0 说成检查通过。每个问题最多列出六个引用来源，需完整清单时另行核对。PowerShell 先设置 `$env:PYTHONIOENCODING = 'utf-8'` 再运行命令；Python 不可用时，说明限制并改为有范围的人工核查，不报脚本通过。
4. **补脚本量不出的人工判断**：实际导航能否到正文、相关来源是否可达、恢复清单是否过期、需要复核的状态是否仍有效；这些材料不存在时不强求创建。结合用户真实问题判断库能否改善回答，见 [效果验收](evaluation.md)。
5. **报告**：结论先行 → 一行体量（页面数/链接数/坏链数）→ 按影响排序的问题（每条带具体路径和计数）→ 分级处置 → 一个收尾问题。
6. **停在只读。** 评估请求不写库；改动等用户选中某一级再动，并把要改的页面和范围先说出来。

## 判读：哪些算真问题

| 现象 | 为什么是问题 |
|---|---|
| 坏链集中在原始资料或 `source_refs` | 核实原始材料是否可达、结论是否还有其他来源；脚本本身不检查 `source_refs` 路径 |
| 同一 basename 出现在两个目录 | 短链接可能难以判断指向；核实实际解析结果，必要时使用带目录的链接 |
| 同一目录里两篇名称相近的说明 | 可能重复，须比较实际职责和内容后再判断 |
| 整片目录缺若干字段 | 先核实本库是否采用这些字段，再判断是否影响检索或维护 |
| 孤立正式页 | 脚本未发现受支持的入链；可能由其他格式、搜索或约定入口访问，需人工判断 |
| 收件箱条目超 30 天 | 根据文件名推算的待处理候选；需核对日期、状态和是否已经归档 |
| `恢复说明` 自称缺失 N 个 | 恢复清单是一次性快照，之后页面被重写或挪位它就过期了 |

## 陷阱

- **恢复/迁移来的库，文件 mtime 全部相同，不能当事实日期用。** 时间和有效性只认 frontmatter 的 `updated`、条目里的观察日，且 `updated` 也不等于事实生效日。
- **“清单说缺” ≠ “真的缺”。** 逐条 `Test-Path` 一遍：路径变了但正文还在的，算现存（挪位/改索引），不算丢失；只有正文确实没有的才进“需重导/永久留空”。把两类混在一起报，用户会以为丢了东西。
- **模板里的 `{{date}}`/`{{title}}` 占位是正常的**，别当成页面缺陷报。
- **不要因为坏链多就断言内容丢了**，也不要顺手“整理目录”——评估阶段重排结构会让用户失去唯一熟悉的地图。
- 体量与历史日志对不上可能来自统计范围、搬迁或内容缺失，先如实报告规模差，再核对原因。
- **`pages_missing_fields` 只在库已采用那套字段规范时才算问题。** 若本库只采用 `title`/`updated`，可用 `--req title,updated` 检查，并在报告中说明口径；只读体检不为此改写维护约定。
- **脚本只检查部分链接。** 带目录的 Markdown 页面路径按完整路径核对，普通 `# 标题` 可检查；同页标题也在检查范围内。重名短链接列在 `ambiguous_links`；块引用、多级标题和部分带格式的标题列在 `unverified_anchors`，需人工核实。
- **候选不等于最终结论。** 脚本不解析 Markdown 格式链接、别名或附件链接，也不完整识别示例代码、特殊标题与字段值；这些可能造成遗漏或误报。`wikilinks: 0` 时应明确说明链接未被脚本校验，不为适配脚本改写现有导航。
