# 个性化选读

只在用户请求选读、收集文章或周刊，或已授权的选读任务运行时使用。建库、普通咨询和安装技能不自动收集内容，也不创建调度。本文支持手动、每日和每周选读；默认手动或每日最多一篇，每周最多三篇，均允许零推荐。

## 先确定本轮需要

沿技能的个人化读取流程，先读维护约定、当前入口和相关主页面。提取会改变选择的当前目标、知识基础、时间或精力限制、阅读偏好、排除项和同类反馈。核对来源、事实日期及替代范围，不把旧状态当今天事实，不把 Agent 推断当用户要求。

已有信息足够就开始，不重新采访用户。只在缺口会改变选题时补问一个关键问题；个人依据不足时，说明当前只能按用户明确主题选读，不编造契合理由。用户要求只读时，全程只在聊天交付，不创建配置、日志或反馈文件。

先复用用户指定的来源、已有选读设置和推荐历史。仅在需要时确定本轮主题与形式，不要求每位用户填大配置，也不预建空模板。已有持续授权按其范围使用；选读授权不等于修改个人画像、上传私人资料或对外发送的授权。

## 收集与全文筛选

主动发现、入口五项筛查、营销识别、跨主题来源分级及工具规则见 [来源与采集](reading-sources.md)。按该参考选择与读取候选，再执行下列文章审核；推荐数量与审核数量分开，来源分级不阻塞本轮交付，工具成功不等于全文完整。

1. 从用户指定来源和公开网络收集候选，可使用已有 RSS 或订阅连接。用户指定“只从这些来源选”时遵守该范围；来源不足就如实报告。不要要求安装特定服务，不自写爬虫或采集脚本，不把无关个人信息带入搜索。
2. 按主题、来源、标题、日期和简介粗筛，至少比较三个不同候选。RSS 摘要、搜索摘要和社交转述只能用于初筛。结合用户目标选择近期内容或仍有效的旧文，不用新旧日期代替质量判断。
3. 对初筛入选的候选读取完整原文；周刊需读相应完整期次，不能只看目录或宣传页。核对正文是否完整，截断片段、二手总结、仅有摘要、付费墙或无法取得正文均不满足条件。可以使用现有可访问的合法来源补读。单一来源失败后仍可处理其余候选；需要联网检索或补读而剩余能力无法完成本轮条件时，明确限制并停止本轮推荐，不把摘要包装成读过全文。用户已提供完整来源材料时，可在说明未联网的前提下按这些材料选读。
4. 全文审核同时满足两道门槛。内容质量：论证或实践有依据，标题与正文一致，关键条件与局限清楚，信息仍有效；按来源参考中的文章类型检查，并写明正文依据及具体问题，不用无解释的总分。个人契合：能帮助用户当前问题，难度与其基础相符，阅读成本与预期价值相称，并符合排除项。任一道不满足就淘汰本篇推荐，初筛评价不能覆盖全文发现的问题。来源状态与样本如何处理，按来源参考执行。
5. 在合格项中按当前帮助价值取少量内容。同一观点的重复文章不占名额；现成周刊按一项计。只有一篇合格就推荐一篇，全部不合格就零推荐。合理补搜后仍不足三个可比较候选时，不降门槛或无限扩大主题，本轮不形成最终推荐，并说明候选不足。

手动执行时，简要说明零推荐的原因。定时执行没有合格内容时不发送空简报，在已授权的记录位置记“零推荐”及原因；工具故障或全文获取失败记为相应失败，不能都记成“没有好文章”。

## 中文交付与外文讲解

每项交付中文标题、简短导读、具体个人推荐理由、来源及发布日期、原文链接。推荐理由只引用真正影响选择的个人因素，不复述无关隐私；日期不可得就标“发布日期未核实”，不以检索日期代替。首次引用周刊同时写明期次或期次日期。

用户追问“你是通过什么途径找到的”时，报实际用过的查询词、读过全文的链接清单、没使用的途径（未登录平台、未用 RSS／订阅）以及尚不可核实的项；不要把搜索摘要、标签页或目录页说成读过全文。

导读用自己的话说明问题、核心观点与适用边界，保留原文链接，不以长篇摘录代替导读。外文内容默认用中文导读；用户需要时，再解释背景、术语和核心论证。只有用户直接提供原文，或已核实授权或许可允许时，才提供全文译文。明确区分作者原观点、译文和 Agent 的解释或评价；“已经完整阅读”不等于“可以全文转载或翻译”。

手动结果直接呈现在当前聊天。仅在用户已授权具体交付位置、且现有工具支持时才向该位置发送；没有发送工具或授权就交付可审阅内容，不能声称已经送达。

## 私有记录、去重与反馈

推荐历史、配置和反馈保存在用户授权的私有位置，优先复用现有记录；不得写入共享技能或作为公开示例。无需新数据库，少量 Markdown 记录即可。持久写入按 [维护与反馈](maintenance.md) 核对权限；没有记录权限时仍可完成手动只读选读，并明确“本次可用当前上下文去重，无法保证跨期去重”。

按原文链接及周刊期次跨期核对，必要时使用来源给出的规范链接识别同文；只去除能确认的追踪参数，不能删除可能改变正文的参数。周选默认排除已在日选或更早周期呈现、送达的内容。用户明确要求“本周回顾”时可以重列，并标注已推荐日期。已筛中但尚未呈现、发送失败或回执未知的内容不冒充成功推荐；再次发送前先核对记录及可查的渠道历史或回执。

区分候选检索、全文筛选、已呈现和成功送达：搜索到链接只算检索；读全文并通过审核只算筛中；当前聊天展示算已呈现；外部渠道有明确成功回执才记成功送达。回执未知保持未知，先查历史，不直接重发。确认失败后，仅在原授权内纠正原因并有限重试；仍失败或无法确认就停下报告，不循环发送。

最小运行记录可采用下例。字段随真实发生的步骤填写，不要求为每个粗筛候选建档，不把未发生的步骤填成成功。`筛选`、`呈现`、`发送`分别记状态，避免一个“完成”覆盖所有步骤。

```markdown
## 一次选读（虚构示例）

运行时间与时区：2026-10-27 08:00，Asia/Shanghai
模式与周期：每日，2026-10-27
个人依据：当前用户主页面的相关条目或来源定位，不复制整份画像
候选与结果：比较 4 项，全文审核 2 项，筛中 1 项；另 1 项因论据不足淘汰
内容标识：原文链接；周刊另记期次或期次日期
筛选：已筛中（零推荐或工具失败时改记真实结果和原因）
呈现：已在当前聊天呈现
发送：未请求；如已请求，另记目标、成功／失败／未知及可查回执
反馈：未收到，不解释为不感兴趣
```

用户反馈“有用、太难、过时、不相关”等信息时，按真实语境调整后续选题、难度和时效。无回复不代表负面反馈，一次反馈不形成长期性格结论。文章内容、推荐记录和 Agent 的推荐理由不自动写进稳定画像；用户的实际反馈如何持久写回，继续遵守原有维护权限和证据规则。

## 每日与每周定时运行

“增加选读功能”只授权完善技能；实际启用定时任务需要用户明确请求。创建前从已有约定或本次表达确定频率、执行时间、时区、交付位置、私有记录位置及相应写入或发送范围，只补问尚缺的必要信息。不能从“全权维护信息库”推导调度或对外发送权限。

使用宿主现有调度工具。工具不支持联网、全文读取、记录或所需交付时，说明哪一步不可用，不宣称已启动。保存的任务提示应要求每轮读取有效个人信息与推荐历史、执行全文审核、遵守数量上限和去重规则、零推荐静默并记录结果。工具失败或需要用户处理时按实际情况报告；不要把零推荐静默变成隐瞒任务失败。

检查已有同类任务，优先更新而不重复创建。只有工具确认创建或更新成功后才能报告已启用；未确认的保持待核实。每日与每周任务共享同一份授权内推荐历史；修改或停用按用户请求和宿主工具执行，不额外建立后台监听。
